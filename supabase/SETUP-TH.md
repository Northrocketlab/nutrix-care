## 4. เปิดและทดสอบระบบกลาง

แจ้งผู้พัฒนาว่ารัน SQL และสร้างบัญชีแล้ว จึงเปลี่ยน `dist/cloud-config.js` เป็น `enabled:true` ทดสอบในเครื่องก่อนเผยแพร่

ต้องตรวจ: ผู้ไม่ล็อกอินอ่านไม่ได้, บัญชีที่ไม่อยู่ในรายชื่ออ่านไม่ได้, ผู้ดูแลล็อกอินได้, เพิ่มสัตว์/ย้ายคอก/ตรวจรายเดือนได้, อีกเครื่องเห็นข้อมูล, การบันทึกจากข้อมูลเก่าถูกปฏิเสธและไม่ทับข้อมูลคนอื่น

หน้าเว็บโหลดข้อมูลใหม่ทุก 10 วินาทีขณะที่ใช้งาน และหยุดรับข้อมูลใหม่ระหว่างเปิดแบบฟอร์ม บันทึกใช้ revision ของทั้งศูนย์: หากมีคนอื่นบันทึกก่อน ให้คัดลอกสิ่งที่กรอก ปิดแบบฟอร์ม กดอัปเดต แล้วทำรายการอีกครั้ง ไม่รวมการแก้ที่ชนกันอัตโนมัติ

หากเครือข่ายขาด จะไม่รายงานสำเร็จและไม่สลับไปเขียนข้อมูลในเครื่องเงียบ ๆ หากคำตอบจากเซิร์ฟเวอร์หาย ให้โหลดข้อมูลใหม่เพื่อตรวจว่ารายการถึงเซิร์ฟเวอร์แล้วหรือยัง ก่อนทำซ้ำ

## 5. ข้อมูลเดิมและพนักงาน

ผู้ดูแลกดปุ่มชื่อบัญชี → เลือกไฟล์ JSON → ตรวจจำนวน → ยืนยันนำเข้า ใช้ได้เมื่อฐานข้อมูลยังว่างเท่านั้น ไม่เขียนทับทะเบียนที่มีอยู่ ไม่ย้ายข้อมูลอัตโนมัติ

Sunny ที่ยังมี `placementExample:true` ต้องยืนยันตำแหน่งในต้นแบบก่อนนำเข้า หากไฟล์หลายเครื่องมีข้อมูลต่างกัน ต้องรวมและตรวจรหัสซ้ำก่อนนำเข้า

เพิ่มพนักงาน: สร้างบัญชีใน Authentication แล้วรัน SQL ต่อไปนี้โดยเปลี่ยนอีเมลและชื่อ:

```sql
insert into public.care_members(email,display_name,role)
values('staff@company.com','ชื่อพนักงาน','staff');
```

ทุกบัญชีที่ active เพิ่มสัตว์ ย้ายคอก และบันทึกการดูแลได้ การเพิ่ม/ระงับสมาชิกทำโดยผู้ดูแล Supabase ไม่ให้หน้าเว็บแก้สิทธิ์ตัวเอง

```sql
update public.care_members set active=false where email='staff@company.com';
```

## 6. สำรองก่อนใช้งานจริง

กำหนดผู้รับผิดชอบสำรองฐานข้อมูลและทดสอบกู้คืน ไฟล์ส่งออก JSON เป็นสำเนาข้อมูลแอป ไม่รวมบัญชีผู้ใช้ สิทธิ์ และ care_audit ต้องสำรองฐานข้อมูลแยกตามแผน Supabase; แผน Free ไม่ควรถือว่ามีระบบสำรองพร้อมใช้งานเอง
