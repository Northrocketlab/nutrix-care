# Nutrix Care

เพิ่มสัตว์โดยกรอกชื่อและใช้กรงที่เลือกไว้ได้เลย รหัสสัตว์เป็นข้อมูลไม่บังคับ หากเว้นว่างระบบสร้างรหัสอ้างอิง AUTO- ให้เอง สัตว์ชื่อซ้ำยังแยกประวัติได้ รหัสเดิมยังคงใช้ตามเดิม

เว็บ GitHub Pages: https://northrocketlab.github.io/nutrix-care/

เมื่อเปิด Pages และเลือก Source เป็น GitHub Actions แล้ว การ push ไป main จะทดสอบและเผยแพร่เฉพาะโฟลเดอร์ dist อัตโนมัติผ่าน `.github/workflows/pages.yml` ไม่เผยแพร่ไฟล์สำรองฐานข้อมูล

ตรวจรายเดือนแบบบันทึกเฉพาะปัญหา: เลือกสัตว์จากผังคอกแล้วกดบันทึกปัญหาขน/เล็บ/หู หน้ารายเดือนแสดงตัวที่พบปัญหาตามผลล่าสุดของเดือนนั้น สามารถบันทึกปกติทั้งสามหัวข้อเพื่อปิดรายการเดิมที่มีปัญหาได้โดยเก็บประวัติครบ ไม่บันทึกหรือถือว่าสัตว์อื่นปกติอัตโนมัติ ผลตรวจเดิมยังอยู่ในประวัติสัตว์และรายงาน Excel ทดสอบด้วย `node check-monthly.cjs`

ปุ่ม **รายงาน Excel** ส่งออก `.xlsx` จำนวน 7 ชีต: สรุป ทะเบียนสัตว์ รายการยา ผลตรวจรายเดือน งาน ข้อสังเกต และประวัติกิจกรรม โหลดข้อมูลกลางล่าสุดก่อนส่งออก รวมประวัติย้อนหลัง ไม่รวมรหัสผ่านหรือข้อมูลบัญชี Supabase และไม่ใช้กู้ฐานข้อมูล ทดสอบด้วย `node check-excel.cjs`

เตรียมการเชื่อม Supabase แล้ว ดู `supabase/SETUP-TH.md` และรัน `supabase/setup.sql` ใน Dashboard ก่อนเปิดใช้ ค่า `enabled:false` ใน `dist/cloud-config.js` หมายถึงยังใช้ต้นแบบในเครื่อง ไม่ใช่ฐานข้อมูลกลาง ทดสอบการบันทึกชนกันเพิ่มเติมด้วย `node check-cloud.cjs`

เว็บต้นแบบสำหรับบันทึกสัตว์ ตำแหน่งคอก และงานดูแลในศูนย์ Nutrix ออกแบบให้ใช้งานบนมือถือ

## เปิดทำต่อบนคอมเครื่องอื่น

1. ดาวน์โหลด repository นี้ หรือ clone ด้วย Git
2. ติดตั้ง Node.js
3. เปิด terminal ในโฟลเดอร์โปรเจกต์ แล้วรัน `node serve.cjs` หรือ `npm start`
4. เปิด http://localhost:4173

ไม่ต้องติดตั้ง dependencies หรือ build ก่อนใช้งาน ตรวจสอบโปรเจกต์ด้วย `node check.cjs` หรือ `npm test`

## การเก็บข้อมูล

ระบบปัจจุบันเปิดใช้ Supabase แล้ว (`enabled:true` ใน `dist/cloud-config.js`) ข้อมูลจริงเก็บในฐานข้อมูลกลาง ผู้ใช้งานต้องล็อกอินด้วยบัญชีที่ยืนยันอีเมลและมีรายชื่อ active ใน care_members จึงจะอ่านหรือแก้ไขได้ การเปิดหน้าเว็บหรืออ่านโค้ดสาธารณะไม่ให้สิทธิ์เข้าถึงข้อมูลสัตว์ คีย์ใน cloud-config.js เป็น publishable key ซึ่งเปิดเผยได้ ไม่ใช่ service role key

เมื่อเปลี่ยน URL ต้องล็อกอินใหม่ แต่ใช้ฐานข้อมูลและบัญชีเดิม เซสชันเก็บใน sessionStorage โดยค่าเริ่มต้น หากเลือก “ล็อกอินค้างไว้” จะเก็บเซสชันใน localStorage เพื่อเปิดเบราว์เซอร์ครั้งถัดไปได้ กดออกจากระบบเพื่อล้างเซสชันที่จำไว้ ไม่เก็บรหัสผ่าน ส่วน localStorage key `nutrix-care-prototype-v1` ใช้เฉพาะโหมดต้นแบบที่ปิด cloud เท่านั้น

ข้อมูล Sunny มาจากตัวอย่างที่ผู้ใช้ให้ ตำแหน่งเริ่มต้น D1-A01 เป็นตำแหน่งสาธิต ข้อมูลสุขภาพและยาไม่ได้สมมติขึ้น อายุคำนวณจากวันเกิด และวันที่ใช้เขตเวลา Bangkok ทิศทางและหมายเลขแถวควรตรวจยืนยันกับสถานที่จริง

## ขั้นต่อไปสำหรับใช้งานร่วมกัน

เพิ่มพนักงานผ่านบัญชี Supabase Auth และ care_members ห้ามนำรหัสผ่าน service role key ไฟล์ secrets.xml หรือไฟล์สำรองฐานข้อมูลมาใส่ repository นี้ รายการยาปัจจุบันยังไม่ใช่บันทึกการให้ยาแต่ละครั้ง

GitHub เก็บ source code และ workflow เผยแพร่ไป GitHub Pages ส่วนเว็บไซต์ Sites เดิมต้องเผยแพร่แยกต่างหาก

หากข้อมูลเดิมอยู่ในกรง A15/B15 ของคอก 1 หรือ 3 ระบบเก็บข้อมูลไว้และแจ้งให้ย้ายไปกรงที่ถูกต้อง ไม่ลบหรือย้ายสัตว์อัตโนมัติ

อัปเดตฐานข้อมูลเดิมตามผังล่าสุดด้วย `supabase/update-kennel-layout.sql` สคริปต์แก้เฉพาะรายการกรง เพิ่ม D2-A16 และนำ 6 รหัสที่ยกเลิกออก โดยไม่เปลี่ยนข้อมูลสัตว์หรือประวัติ

ทดสอบตัวเลือกล็อกอินค้างไว้ด้วย `node check-login-session.cjs` ใช้ Supabase SDK ตัวเดียวกับเว็บและ Auth จำลอง ครอบคลุมการปิดเปิดเบราว์เซอร์ การไม่เลือกจำเซสชัน การออกจากระบบ และการล็อกอินผิด
